-- Hive metastore - you can create tables over the data  in cloud storage (tables, view, functions) -- lack fine grained access control like row and column level access,
lack of audit logging, lineage support for multi cloud environment 

-- dbfs-- databricks file system is a distributed file system that is fully integrated within databricks - provide abstraction layer over cloud storage such as ADLS
for ex . in azure databricks , you can simply mount a container from the ADLS into dbfs and access it similar to accessing a shared drive on your computer
 
-- Unity catalog -- similar to hive-- also allows us to create tables and views on structure data , functions , offers us another object called volume which is an abstraction layer
on top of files in the cloud storage
Unified solution for accessing files as well as table objects
offers data lineage, data security, data governance

-- UNITY catalog objects -- 
	*storage credentials-authentication mechanism for accessing the data stored in azure storage on behalf of user- created with managed identity
 		or a service principle -- access connector for databricks
 	*external location -- combines the storage credential with the cloud storage container to gain access to the specific container in cloud storage
